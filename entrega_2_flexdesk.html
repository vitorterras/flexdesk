1. Arquitetura de Software (Aulas 07, 08 e 09)

Para atender aos requisitos operacionais do FlexDesk, adotou-se a Arquitetura em 3 Camadas (3-Tier Layered Architecture), garantindo alto desacoplamento, reuso de regras de negócio, manutenibilidade e testabilidade isolada das camadas.

1.1 Estilo Arquitetural em 3 Camadas

  • 1. Camada de Apresentação (Presentation Layer - UI): Responsável pela interface interativa do usuário. Implementada em **Streamlit (Python)** com componentes visuais responsivos (`auth_ui`, `map_ui`, `reservation_ui`, `resource_admin_ui`, `dashboard_ui`).
  • 2. Camada de Negócio e Serviços (Business Logic Layer - Domain Services): Concentra as regras de validação, limites de agendamento, cálculo de tempo real, prevenção de colisão e disparo de W.O. (`AuthService`, `ReservationService`, `ResourceService`, `DashboardService`).
  • 3. Camada de Acesso a Dados e Persistência (Data Access Layer - Repository): Gerencia o ciclo de vida das entidades (`Usuario`, `Recurso`, `Reserva`, `Localizacao`, `Perfil`) e abstrai as consultas ao banco de dados SQLite (`DatabaseRepository`).

1.3 Decisões de Design e Atributos de Qualidade

• Desempenho e Concorrência: O status do mapa em tempo real é calculado dinamicamente com consultas filtradas por horário e indexação de `recurso_id` e `data_hora_inicio`.

• Segurança: Senhas são armazenadas utilizando função Hash criptográfica SHA-256 com salting. O domínio do e-mail é validado na camada de serviço contra domínios corporativos permitidos.

• Manutenibilidade: A separação estrita de responsabilidades em 3 camadas permite substituir o banco de dados (ex: SQLite por PostgreSQL/Supabase) ou a interface visual sem alterar a camada de negócio.

3. Produto Mínimo Viável (MVP) e Banco de Dados Supabase

O Produto Mínimo Viável (MVP) do FlexDesk foi evoluído para uma **Aplicação Web Nativa em React 18 + Vite + TypeScript + TailwindCSS** com estética **Liquid Glass Dark Mode**, alimentada por um servidor API **FastAPI** em Python e integrada ao banco de dados relacional **Supabase**.

3.1 Banco de Dados Relacional no Supabase

• Projeto Supabase Conectado: Projetos Pessoais (ID: nfhiqwyvluoqzluzuxup)

• Tabelas Criadas e Povoadas: perfil, usuario, localizacao, recurso, reserva.

• Integridade Referencial: Chaves Primárias, Chaves Estrangeiras, restrições UNIQUE e índices otimizados para concorrência (idx_reserva_recurso_horario).

5. DevOps, Integração e Entrega Contínua (Aula 13)

Alinhado às melhores práticas de DevOps, o projeto FlexDesk utiliza um pipeline de Integração Contínua (CI) automatizado via GitHub Actions. O workflow é disparado a cada `push` ou `pull_request` nos branches principais.

5.1 Pipeline do GitHub Actions (`.github/workflows/ci.yml`)
