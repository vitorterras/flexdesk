1. Definição do Escopo

O FlexDesk é uma solução de software desenvolvida para solucionar problemas logísticos e organizacionais em escritórios de coworking e empresas que adotam o modelo híbrido de trabalho. Com a flexibilidade das rotinas modernas, o gerenciamento de espaços físicos ociosos ou superlotados tornou-se um grande desafio. O sistema visa otimizar o uso da infraestrutura física através do agendamento intuitivo e inteligente de mesas, salas de reunião e cabines de chamada.

Problema Específico a ser Resolvido

  • Falta de Visibilidade de Ocupação: Colaboradores/Clientes se deslocam até o espaço sem a garantia de que haverá mesas ou salas de reunião adequadas disponíveis.
  • Uso Ineficiente da Infraestrutura: Salas de reunião permanecem bloqueadas ou ociosas sem o devido controle de presença.
  • Falta de Métricas para Gestão: Os gestores do espaço não possuem dados concretos para decidir sobre expansão de layout, corte de gastos com aluguel ou alocação de recursos.

Clientes e Stakeholders

  • Clientes (Empresas Residentes / Usuários Finais): Profissionais liberais ou colaboradores de empresas que buscam reservar estações de trabalho rápidas, salas de reuniões para clientes ou cabines privadas para chamadas importantes.
  • Gestores de Facilities / Administradores de Coworking: Responsáveis pela manutenção, cadastro de recursos e análise operacional de ocupação dos ambientes.

  • Histórias Associadas: US001 (Autenticação) e US002 (Visualização do Mapa).
  • Tarefas de Desenvolvimento (Tasks):

Sprint 2: Motor de Reservas e Regras de Check-in (Semanas 4 a 6)

  • Histórias Associadas: US003 (Reserva de Mesas/Salas) e US004 (Check-in).

    • Modelagem da lógica de colisão de horários no banco de dados para evitar reservas duplicadas.
    • Construção do formulário e calendário de solicitação de reserva.
    • Implementação do mecanismo de check-in geolocalizado ou via webapp com timeout de cancelamento automático.

Sprint 3: Administração e Relatórios Gerenciais (Semanas 7 a 9)

  • Histórias Associadas: US005 (Cadastro de recursos) e US006 (Dashboards).

    • Desenvolvimento das telas de CRUD de salas, andares e mesas para gestores de facilities.
    • Criação de consultas agregadas para gerar métricas de ocupação de assentos.
    • Integração de biblioteca gráfica no front-end para exibir painéis interativos.
    • Validação final integrada do fluxo ponta a ponta com usuários reais.

Detalhamento Técnico dos Casos de Uso

Autenticar Usuário (UC001)

Ator Principal: Colaborador / Gestor de Facilities

Pré-condição: O usuário deve possuir cadastro ativo no sistema com e-mail institucional válido.

Fluxo Normal:

  1. O usuário acessa a tela de login do sistema.
  2. O usuário informa seu e-mail institucional e senha.
  3. O sistema valida o domínio do e-mail contra os domínios institucionais permitidos.
  4. O sistema verifica a senha informada contra o hash armazenado no banco de dados.
  5. O sistema consulta o perfil de acesso do usuário (Colaborador ou Gestor) na tabela PERFIL.
  6. O sistema inicia a sessão autenticada e redireciona o usuário para a tela principal correspondente ao seu perfil.

Extensões e Exceções:

  • 3a - Domínio Inválido: Se o domínio do e-mail não pertencer à lista de domínios permitidos, o sistema rejeita o login e exibe mensagem de erro orientando o uso do e-mail corporativo.
  • 4a - Credenciais Incorretas: Se e-mail ou senha não corresponderem, o sistema exibe mensagem genérica de erro (sem especificar qual campo está incorreto) e registra a tentativa.
  • 4b - Conta Bloqueada: Após 5 tentativas falhas consecutivas, o sistema bloqueia temporariamente o acesso e notifica o administrador.

Pós-condição: O usuário está autenticado no sistema com sessão ativa e permissões condizentes com seu perfil de acesso.

Visualizar Mapa do Escritório (UC002)

Ator Principal: Colaborador

Pré-condição: O colaborador deve estar autenticado no sistema (UC001). Devem existir recursos cadastrados e associados a uma localização.

Fluxo Normal:

  1. O colaborador acessa a tela de mapa do escritório.
  2. O sistema inclui o caso de uso Autenticar Usuário (UC001) para validar a sessão ativa.
  3. O sistema consulta todos os recursos ativos agrupados por localização (andar/setor) via tabela LOCALIZACAO.
  4. Para cada recurso, o sistema determina o status em tempo real verificando se existe reserva ativa com status_reserva = 'Em Uso' ou 'Pendente' no horário atual.
  5. O sistema renderiza o mapa visual com os recursos coloridos conforme o status: verde (Livre), vermelho (Ocupado/Reservado) e azul (reserva do próprio colaborador logado).
  6. O colaborador pode clicar em um recurso livre para iniciar o fluxo de reserva (estende para UC003).

Extensões e Exceções:

  • 3a - Sem Recursos Cadastrados: Se não houver recursos ativos na localização selecionada, o sistema exibe mensagem informativa e sugere contato com o gestor de facilities.
  • 6a - Recurso Clicado Indisponível: Se o recurso for ocupado entre o carregamento e o clique do colaborador, o sistema atualiza o status na tela e informa a indisponibilidade.

Pós-condição: O colaborador visualiza o estado atualizado de todos os recursos do escritório e pode prosseguir para realizar uma reserva.

Reservar Espaço (UC003)

Ator Principal: Colaborador

Pré-condição: Colaborador deve estar devidamente autenticado (UC001).

Fluxo Normal:

  1. O colaborador solicita a reserva de uma estação de trabalho ou sala.
  2. O sistema inclui o caso de uso Autenticar Usuário (UC001) para validação de privilégios.
  3. O colaborador inclui o caso de uso Visualizar Mapa (UC002) para selecionar a mesa ou sala livre de seu interesse.
  4. O colaborador informa a data, hora de início e término desejadas.
  5. O sistema valida a disponibilidade do recurso selecionado no intervalo informado.
  6. O sistema registra a reserva e envia uma notificação de confirmação por e-mail para o colaborador.

Extensões e Exceções:

  • 5a - Recurso Indisponível: Se houver colisão de horários no banco, o sistema exibe uma mensagem de alerta e solicita que o colaborador informe outra mesa ou altere o período.
  • 5b - Horário Inválido: Se a data informada for anterior à data corrente, o sistema rejeita a operação e solicita nova entrada de dados.

Pós-condição: A estação/sala de reunião é marcada como reservada no banco de dados para o intervalo de tempo solicitado, impedindo reservas sobrepostas.

Efetuar Check-in (UC004)

Ator Principal: Colaborador

Pré-condição: O Colaborador deve possuir uma reserva pendente para o horário atual.

Fluxo Normal:

  1. O colaborador acessa o sistema com uma reserva pendente para o horário atual.
  2. O sistema inclui o caso de uso Autenticar Usuário (UC001).
  3. O sistema lista as reservas pendentes do colaborador para o horário corrente.
  4. O colaborador confirma o check-in na reserva desejada.
  5. O sistema valida se o horário atual está dentro da janela de tolerância de até 15 minutos do início programado.
  6. O sistema altera o status da reserva para "Em Uso" e registra o horário do check-in.

Extensões e Exceções:

  • 4a - Fora da Janela de Check-in: Se o colaborador tentar realizar o check-in muito antes ou após o limite de tolerância, o sistema exibe mensagem de erro e bloqueia a ação.
  • 4b - W.O. (No-Show): Se passarem 15 minutos do início programado sem check-in, o sistema cancela automaticamente a reserva, liberando o recurso para novos agendamentos.

Pós-condição: O status do assento no mapa em tempo real muda para "Ocupado".

Gerenciar Recursos (UC005)

Ator Principal: Gestor de Facilities

Pré-condição: O gestor deve estar autenticado com perfil de acesso "Gestor" (UC001).

Fluxo Normal:

  1. O gestor acessa o painel administrativo de gerenciamento de recursos.
  2. O sistema inclui o caso de uso Autenticar Usuário (UC001) e verifica se o perfil possui permissão de gestão.
  3. O gestor seleciona a operação desejada: cadastrar, editar ou remover um recurso.
  4. [Cadastrar] O gestor preenche código de identificação único, tipo (Mesa, Sala, Cabine), capacidade máxima e seleciona a localização (andar/setor) a partir da tabela LOCALIZACAO.
  5. [Editar] O gestor seleciona um recurso existente, altera os campos desejados e confirma.
  6. [Remover] O gestor seleciona um recurso e confirma a remoção. O sistema verifica se não há reservas futuras ativas para o recurso antes de prosseguir.
  7. O sistema persiste as alterações e atualiza o mapa de visualização em tempo real.

Extensões e Exceções:

  • 4a - Código Duplicado: Se o código de identificação informado já existir, o sistema rejeita o cadastro e solicita um código único.
  • 6a - Recurso com Reservas Futuras: Se o recurso a ser removido possuir reservas agendadas, o sistema alerta o gestor e bloqueia a remoção, exibindo as reservas conflitantes.

Pós-condição: O catálogo de recursos do sistema está atualizado e o mapa do escritório reflete imediatamente as alterações realizadas.

Visualizar Dashboards de Ocupação (UC006)

Ator Principal: Gestor de Facilities

Pré-condição: O gestor deve estar autenticado com perfil de acesso "Gestor" (UC001). Devem existir registros de reserva no histórico do sistema.

Fluxo Normal:

  1. O gestor acessa o módulo de relatórios e dashboards.
  2. O sistema inclui o caso de uso Autenticar Usuário (UC001) e verifica o perfil de acesso.
  3. O gestor seleciona o período de análise (diário ou mensal) e o escopo (andar, setor ou toda a unidade).
  4. O sistema executa consultas agregadas na tabela RESERVA, cruzando com RECURSO e LOCALIZACAO para calcular taxas de ocupação por período e por localização.
  5. O sistema exibe gráficos interativos com a taxa média de ocupação por setor/andar e a evolução temporal do uso.
  6. O gestor pode optar por exportar o relatório gerado nos formatos PDF ou CSV.

Extensões e Exceções:

  • 3a - Sem Dados no Período: Se não houver registros de reserva no intervalo selecionado, o sistema exibe mensagem informativa e sugere ampliar o período de consulta.
  • 6a - Falha na Exportação: Se ocorrer erro na geração do arquivo, o sistema exibe mensagem de erro e mantém os dados na tela para nova tentativa.

Pós-condição: O gestor obtém as métricas de ocupação do período consultado e, opcionalmente, um arquivo exportado para uso em tomadas de decisão operacionais.

5. Modelagem Conceitual (DER)

A modelagem de dados proposta define a estrutura física e lógica que sustenta o sistema FlexDesk, garantindo a consistência das restrições e regras de negócio de ocupação de espaços.

Dicionário de Dados Simplificado

Alterações em relação à versão anterior: A tabela USUARIO teve o campo cargo (VARCHAR livre) substituído pela FK perfil_id, que referencia a nova entidade PERFIL — tornando o controle de acesso mais robusto. A tabela RECURSO teve o campo status_atual removido (status agora é derivado das reservas ativas em tempo real) e ganhou a FK localizacao_id, referenciando a nova entidade LOCALIZACAO, necessária para suportar os relatórios por setor/andar do UC006.

Tabela: PERFIL

Campo Tipo de Dados Chave Descrição
id INT (AUTO_INCREMENT) PK Identificador único do perfil de acesso.
nome VARCHAR(50) (UNIQUE) - Nome do perfil (Ex: 'Colaborador', 'Gestor'). Valor controlado, não livre.
descricao VARCHAR(255) - Descrição das permissões e responsabilidades do perfil.

Tabela: USUARIO

Campo Tipo de Dados Chave Descrição
id INT (AUTO_INCREMENT) PK Identificador único do usuário no sistema.
nome VARCHAR(100) - Nome completo do colaborador ou gestor.
email VARCHAR(100) (UNIQUE) - E-mail institucional usado para login.
senha_hash VARCHAR(255) - Senha de acesso armazenada de forma criptografada (bcrypt).
perfil_id INT FK → PERFIL Define o nível de acesso do usuário via referência à tabela PERFIL. Substitui o campo cargo da versão anterior.

Tabela: LOCALIZACAO

Campo Tipo de Dados Chave Descrição
id INT (AUTO_INCREMENT) PK Identificador único da localização física.
nome VARCHAR(100) - Nome descritivo da área (Ex: 'Ala A', 'Coworking Open Space').
tipo VARCHAR(30) - Classificação da área ('Setor', 'Andar', 'Ala').
andar INT - Número do andar onde a localização se encontra. Utilizado para agrupamento nos relatórios do UC006.

Tabela: RECURSO

Campo Tipo de Dados Chave Descrição
id INT (AUTO_INCREMENT) PK Identificador único do recurso físico.
codigo_identificacao VARCHAR(20) (UNIQUE) - Etiqueta/Identificador físico do recurso (Ex: 'Mesa A-12', 'Sala 4B').
tipo VARCHAR(20) - Categoria do espaço ('Mesa', 'Sala Reunião', 'Cabine').
capacidade INT - Capacidade máxima de pessoas suportadas.
localizacao_id INT FK → LOCALIZACAO Associação com a localização física (andar/setor) onde o recurso se encontra. Substitui o campo status_atual, cujo valor passa a ser derivado das reservas ativas em tempo real.

Tabela: RESERVA

Campo Tipo de Dados Chave Descrição
id INT (AUTO_INCREMENT) PK Identificador único do agendamento.
usuario_id INT FK Associação com o Colaborador que fez a reserva.
recurso_id INT FK Associação com a Mesa ou Sala de Reunião reservada.
data_hora_inicio DATETIME - Início previsto da utilização do recurso.
data_hora_fim DATETIME - Fim programado da utilização.
status_reserva VARCHAR(20) - Estado do agendamento ('Pendente', 'Confirmada', 'Cancelada', 'Em Uso').
data_checkin DATETIME (NULLABLE) - Horário exato no qual o colaborador realizou o check-in.
